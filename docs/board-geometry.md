# AURORA 盤面の当たり判定修正（2026-10-28）

720×960 の assets/aurora.webp に合わせて、液晶下の透明ステージを8本の上面として定義した。中央の347〜373pxは落とし口として開けている。手前のプラスチックに重なる金の装飾は釘扱いから除外し、残りの釘IDは維持した（411本）。

液晶の下隅は矩形ではなく、(188,464)→(264,504)、(456,504)→(532,464)の斜辺。旧矩形はステージの左入口を塞いでいた。

START の口・描画・入賞判定は engine.js の START を共有する。上から口を横切った玉のみ入賞し、左右の壁や下からの侵入は入賞しない。描画は pachinko-pocket.js の金の頬枠、奥行きのある口、下側の銘板で構成する。

物理更新は時間（最大1/240秒）と移動距離（玉半径の半分）の両方で細分化し、細い釘・ガイドのすり抜けを防ぐ。上面は低速時に跳ね返さず法線速度のみを止める。下側の玉を上面へ吸い上げない。

## 検証

- 30/60/120fpsで左右ステージから中央落とし口へ到達。
- 高速衝突、上面の表裏、斜め液晶下端、STARTの正面入賞・横/下/逆向きの拒否を回帰テスト。
- 盤面画像に実際のCanvas描画と軌跡を重ねて確認。
- ブラウザー（Chromium）で実際に発射して、ステージを転がる玉と入賞を確認。

## 入賞頻度への影響と調整

ステージを当たり判定にしただけだと、中央の落とし口が真下のヘソへ玉を運び、START入賞が約60〜75%になった（STARTは1発で3発戻るため、大当たりなしで持ち玉が増える）。

実機のステージは手前に張り出した棚で、転がる玉の多くは中央の溝に届く前に手前へこぼれる。平面の盤ではこれを「ステージに乗っている間、1秒あたり STAGE_SPILL（=3）の割合で手前に落ち、その玉は以後ステージを通り抜ける」で表した。見えない壁は足していない。

| 状態 | START入賞（発射強度30〜45%、各300〜400発） |
| --- | --- |
| ステージなし（調整前のmain） | 約7% |
| ステージあり・こぼれなし | 57〜74% |
| ステージあり・こぼれ STAGE_SPILL=3 | 約5〜8% |

ブラウザーで発射強度45%のまま90秒遊んだ結果：調整前のmain 1,000→876（START 9回）、こぼれなし 1,000→1,173（30回）、調整後 1,000→891（14回）。抽選確率1/99、入賞の払い出し、役の抽選表は変えていない。

## 釘とのこすれ（2026-10-31）

液晶の左を落ちてきた玉が左下の道釘に当たっても、跳ね返る向きの速さしか減らず、釘に沿う向きの速さはそのまま残っていた。そのため道釘の列が滑り台のようになり、玉が速いまま列の上を滑ったり飛び越えたりしていた（道釘の上にいる時間は平均約0.3秒、当たったあとの最高速度は約380〜470）。

`NAIL_FRICTION` を足した。釘へ向かう速さが `hard`（60）より大きい強い当たりでは、跳ね返る力の `grip`（0.4）倍だけ釘に沿う速さも失い（摩擦）、釘に触れている間は1秒あたり `roll`（1）の割合で速さが落ちる。ゆっくり触れているだけの玉には摩擦をかけないので、釘の上で止まらない。道釘の上にいる時間は約0.9秒、当たったあとの最高速度は約220〜330になった。

これまでのSTART入賞の約半分は、速すぎる玉が道釘の上を飛んでヘソに入るものだった。減速させるとこの入り方はほぼ無くなり、START入賞が約4%に下がったので、STAGE_SPILL を 3 から 0.25 に下げた（ステージ中央からヘソへ入る玉が増える）。

| 状態 | START入賞（発射強度30〜50%、計約3,000発） |
| --- | --- |
| 変更前（摩擦なし・STAGE_SPILL=3） | 約6.2% |
| 摩擦あり・STAGE_SPILL=0.5 | 約4.2% |
| 摩擦あり・STAGE_SPILL=0.25 | 約5.3% |

ブラウザーで発射強度45%のまま90秒：変更前 999→858、変更後 999→855。
